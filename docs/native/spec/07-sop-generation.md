**Notation used in this document.**

- Several Electron strings contain U+2014 (EM DASH). This document never prints that character. Wherever it occurs in a quoted string it is written as the escape `\u2014`, and the C# literal must contain that exact character (C# accepts the same `\u2014` escape inside a string literal, so copying the quoted text into C# source is exact). The same convention is used for every other non-ASCII character in a quoted string: `\u2019` (RIGHT SINGLE QUOTATION MARK), `\u2026` (HORIZONTAL ELLIPSIS), `\u00B7` (MIDDLE DOT), `\u25B8` (BLACK RIGHT-POINTING SMALL TRIANGLE), `\u2699` (GEAR), `\u2728` (SPARKLES), `\u21A9` (LEFTWARDS ARROW WITH HOOK). Any quoted string without an escape is pure ASCII: in particular every `'` and `"` inside the prompt text is ASCII unless written `\u2019`.
- Text inside fenced blocks marked `text` is quoted verbatim, character for character, with the escapes above. A fenced block never has a trailing newline unless the text says so.
- `trim(x)` means JavaScript `String.prototype.trim`, ported as `JsString.Trim` (spec 01, `ShotAI.Core.Json`), never C# `string.Trim()` (they disagree on U+FEFF and a few other code points). "Truthy" for a string means non-empty (whitespace-only is truthy).
- `n` for a step always means its SOP number: the 1-based index of the step within the source list (2.3.1), counting text steps.

### 2.2 The system prompt

`buildSystemPrompt()` (`claude-service.ts:307-313`):

```
parts = [BASE_SYSTEM_PROMPT, TONE_PROMPT[sop.tone]]
custom = trim(sop.customInstructions)
if custom !== '': parts.push('Additional instructions from the user:\n' + custom)
return parts.join('\n\n')
```

`BASE_SYSTEM_PROMPT` is these seven paragraphs joined with `"\n\n"` (`claude-service.ts:181-199`). Paragraph 1:

```text
You are an expert technical writer turning a captured screen recording into a polished Standard Operating Procedure (SOP) by EDITING the project in place. You are given an ordered sequence of steps: each screenshot step (labeled "Screenshot step N") has the exact click point marked on the image with a colored ring (a circle), plus metadata (application/window, an auto-generated caption); author-written "Text step" entries are interleaved.
```

Paragraph 2:

```text
Return an edit plan (structured output) that improves the project IN-LINE: for every screenshot step, write a concise, action-oriented `caption` (the step title, e.g. "Open the navigation menu") and a clear instruction `body` (the detail the reader follows). You may add a leading `intro` (heading + body) and, where the procedure shifts to a new phase, a `sectionHeading`/`sectionBody` inserted before a step \u2014 this renders as a NON-counted phase-divider heading, not a numbered step, so use it to separate phases rather than to add instructions. Always set `title` to a clear, descriptive name for the overall procedure.
```

Paragraph 3 (the numbering paragraph, added by #108, `76b1ad6`):

```text
Set each entry's `stepNumber` to the number in that screenshot's own "--- Screenshot step N ---" heading. Those numbers count the author's text blocks as well as screenshots, so they are often NOT 1, 2, 3 and may skip values entirely \u2014 a project whose first item is a text block has its first screenshot at step 2. Copy each number exactly as it appears and never renumber them into a fresh sequence. An entry whose `stepNumber` does not match a screenshot heading is discarded.
```

Paragraph 4:

```text
Write each instruction about the control inside or directly under the marked ring \u2014 that ring is exactly where the user clicked, so describe THAT element, not some other field on the screen. If the screenshot does not show the result of the click (e.g. a menu or dropdown that opened only after clicking is not visible), describe the click itself and do not invent the resulting menu or its contents.
```

Paragraph 5:

```text
Some steps include a "UI element" line in their metadata \u2014 the accessibility name and control type (e.g. Button, MenuItem, Hyperlink) of the control under the click, read from the operating system. Treat it as a STRONG, reliable signal for WHICH control was clicked. But choose the FRIENDLIEST name for the reader, based primarily on the screenshot: the accessibility name is occasionally technical or internal (e.g. an internal class/identifier, an overly long tooltip, or a developer string) rather than the label a person sees. When the element name and the visible on-screen label differ, name the control by what the user actually sees on screen; use the accessibility name only to confirm the target or when no clear visible label exists.
```

Paragraph 6:

```text
Keep the screenshots in their original order \u2014 do not drop, reorder, or merge them; you only rewrite their text and insert text blocks between them. Ground every instruction in what the screenshots and metadata actually show; never invent UI elements, values, or steps that are not evidenced. Leave author-written text steps alone. Do not transcribe or guess at any redacted/blurred regions of the images.
```

Paragraph 7 (ported from macOS #113, added in `76b1ad6`):

```text
If you have nothing worth saying in the overview, set `intro` to null rather than filling it with a generic or restated heading \u2014 an empty or filler overview is worse than none.
```

### 2.3 Request assembly

`assembleRequest(projectPath)` (`claude-service.ts:328-436`). Order of work:

1. `settings = getSopSettings()`; `{ dir, manifest } = getProjectForRead(projectPath)` (01: gated, not queued, reads the disk).
2. `source = manifest.steps.filter(s => !s.aiInserted)` (`aiInserted === true` excluded; anything else kept) (`:333`).
3. `shotCount = source.filter(s => s.kind !== 'text').length`; `0` throws `Error('This project has no captured screenshots to build an SOP from.')` (`:334-337`). A step with no `kind` key is a shot (capture writes no `kind`; `sop-landing.test.ts:202-208`).
4. `originalById = manifest.sopBackup ? Map(sopBackup.steps by id) : null` (`:340-342`). On duplicate ids the LAST backup step wins (Map semantics).
5. `system = [{ type: 'text', text: buildSystemPrompt() }]`. Note: `buildSystemPrompt` reads settings AGAIN (a second `getSopSettings()`); both reads see the same cached settings object in practice.
6. Content blocks, in this exact order, all in ONE user message (`messages = [{ role: 'user', content }]`):

| # | Block | Present when | Text or payload |
|---|---|---|---|
| 1 | text: header | always | 2.3.2 |
| 2 | text: author overview | `authorIntro(manifest)` non-null (2.3.4) | `authorIntroBlock(intro, manifest.introEditedByUser === true)` (2.3.5) |
| 3..k | per source step, in source order | always | a text step: one text block (2.3.3); a shot step: one image block then one text block (2.3.6) |
| last | text: closing, with `cache_control: { type: 'ephemeral' }` | always | `Now return the inline edit plan as the structured JSON output.` |

REQUIRED. There is exactly one cache breakpoint, on the last block, so a regenerate within the cache lifetime reads the system prompt, every image and all metadata as a cached prefix (`:425-427`).

#### 2.3.1 Numbering

`n = idx + 1` over `source` (text steps counted). The same rule is used by the review list (`SopPanel.tsx:106`, `:292-295`), by apply (`sop-apply.ts:172-187`), and by the render gate label `Step ${n}` (`claude-service.ts:394`). Pre-egress flattening uses a DIFFERENT count (`Step ${shotNo}`, shots only; EDGE-SOP-19). REQUIRED.

#### 2.3.2 Header block and the title instruction

Header text: `titleInstruction(manifest.title, isAutoGeneratedTitle(manifest.title)) + "\n" + tail`, where `tail` is (with `${N}` = `source.length`, the count of ALL source steps, text steps included):

```text
The ${N} steps below are in order. Write one edit-plan entry per SCREENSHOT step, setting its stepNumber to that step's number. Keep the screenshots in this order. Redactions are already baked into the images \u2014 never describe or guess at blurred/obscured areas.
```

There is no plural handling (`The 1 steps below`; Q-SOP-12). `isAutoGeneratedTitle(t)` (01, `project-store.ts:278-282`): `trim(t) === ''` or `/^Project \d{4}\/\d{2}\/\d{2} \d{2}:\d{2}:\d{2}$/` matches `trim(t)` (the generator's format `Project yyyy/MM/dd HH:mm:ss`, `:284-293`).

`titleInstruction(currentName, isAutoGenerated)` (`sop-input.ts:232-251`) returns `lines.join('\n')` of two lines. Line 1: `Current project name: "${currentName}"` (the raw, untrimmed title inside ASCII double quotes; no escaping of quotes inside the name). Line 2 when auto-generated:

```text
That name was generated by the app from a timestamp. It is NOT a title, carries no meaning, and MUST be replaced. Set `title` to a clear, specific name for the PROCEDURE ITSELF, derived from what the steps accomplish \u2014 for example "Configuring VPN access in the admin console", and never return the current name. Every word of the title must come from what the steps actually do; if they are sparse, still name the specific task they show.
```

Line 2 when written by a person:

```text
That name was written by a person, so treat it as intentional. Set `title` to it unchanged unless it is clearly wrong or vague for what the steps actually accomplish, in which case improve it while keeping their meaning.
```

The instruction NAMES NO FILLER WORDS (not `placeholder`, `untitled`, `"SOP"`, `"Project"`): listing them as negative examples made macOS return `placeholder` in the `intro` (#80, `9de16c3`; `sop-prompt.test.ts:75-84`). REQUIRED.

#### 2.3.3 Author text steps

For a text step (`kind === 'text'`) (`claude-service.ts:380-391`):

```
parts = [textStepLabel(n, step.callout)]
if step.heading (truthy): parts.push('Heading: ' + step.heading)     // raw, not trimmed
if step.body (truthy):    parts.push('Body: ' + step.body)           // raw, not trimmed
g = authorBlockGuidance(step.callout); if g: parts.push(g)
text = parts.join('\n')
```

`textStepLabel(n, callout)` (`sop-input.ts:33-39`) is `` `--- ${kind} ${n} (author-written \u2014 leave this content alone) ---` `` where `kind` is from the callout, or `Text step` when the callout is absent, null, or not one of the four known kinds (`isCalloutKind`):

| callout | label kind |
|---|---|
| absent, null, unknown (e.g. `'tip'`) | `Text step` |
| `note` | `Note callout` |
| `caution` | `Caution callout` |
| `warning` | `Warning callout` |
| `section` | `Section heading` |

The number is kept on every kind, matching macOS (`207eddd`). `authorBlockGuidance(callout)` (`sop-input.ts:46-62`): null for absent, null or unknown; for `section`:

```text
(A NON-NUMBERED phase heading the author placed to group the steps that follow. It tells you how they think the procedure divides up \u2014 use that structure rather than inventing your own, keep step wording consistent with the phase it sits in, and do not add a sectionHeading of your own where this already marks the boundary.)
```

#### 2.3.5 The overview block: `authorIntroBlock`

`authorIntroBlock(intro, edited = false)` (`sop-input.ts:136-165`) returns `parts.join('\n')` where `parts = [label, ('Heading: ' + heading)?, ('Body: ' + body)?, '', guidance]` (the heading and body lines are included only when non-empty; they are already trimmed). So the layout is `label\nHeading: h\nBody: b\n\nguidance`.

| mode | label | guidance |
|---|---|---|
| not edited (default) | `--- The author already wrote this overview ---` | permissive, below |
| edited (`introEditedByUser === true`) | `--- The author WROTE this overview themselves \u2014 their words ---` | protective, below |

Permissive guidance:

```text
Treat this as AUTHORITATIVE CONTEXT, not as text to protect. It states intent, audience, scope or constraints that the screenshots cannot show you, and it is the author's own knowledge of the process. Let it inform the whole guide: your `intro` and the wording and emphasis of every step. You may rewrite it freely for clarity, structure and tone \u2014 write the best overview you can. What you must not do is CONTRADICT or SILENTLY DROP the facts and constraints it states; those are things the author knows and you do not.
```

Protective guidance:

```text
This is the AUTHOR'S OWN overview and they have edited it, so their wording states intent, audience, scope or constraints the screenshots cannot show you. Their HEADING is kept exactly as written \u2014 shotAI restores it after you reply, so do not spend effort rewording it. For the BODY: reword only for clarity, grammar and voice, and you may ADD context the steps reveal. Do NOT restructure it, do NOT replace it with your own framing, and do NOT drop any fact, constraint or audience note it states. If it already reads well, return it essentially unchanged \u2014 that is a correct answer here. Substituting a better overview of your own is not.
```

The protective mode must NOT contain the permissive phrases (`rewrite it freely`, `not as text to protect`): the observed failure was the model following the permissive half of a mixed message (#64, `fdc501f`). The prompt says the heading is restored because apply really pins it (2.9.3). REQUIRED.

| Rule | Why | Citation |
|---|---|---|
| A signed-in federated account wins over a stored key | federation is the managed path | `:143-144` |
| A federation-configured but signed-out machine falls back to a key when one exists | a rollout must not strand a user who had a key | `:140-142` |

| The identity token is acquired SILENTLY only | the provider can fire from a background refresh with no user context | `:171-173` |

### 2.8 The structured-output schema

#### 2.8.1 Zod source

`SopEditSchema` (`claude-service.ts:52-75`):

```
z.object({
  title: z.string(),
  intro: z.object({ heading: z.string(), body: z.string() }).nullable(),
  steps: z.array(z.object({
    stepNumber: z.number().int(),
    caption: z.string(),
    body: z.string(),
    sectionHeading: z.string().nullable(),
    sectionBody: z.string().nullable(),

```

`.min(1)` (not `.nonempty()`) makes an empty plan unrepresentable in constrained decoding (#108). The SDK's zod helper forwards `minItems` only for the values 0 and 1; every other constraint (`minimum`, `maximum`, `minLength`, `pattern`, other `minItems`) is RELOCATED into a `description` string the model reads as prose (`lib/transform-json-schema.js`), so a constraint quietly stops being enforced rather than failing with a 400 (`claude-service.ts:37-51`).

#### 2.10.2 429 classification (#113, `1f1794f`)

```
retryAfterSeconds(headers):                                       // claude-service.ts:136-141
    raw = headers.get('retry-after'); if raw == null or !/^\d+$/.test(trim(raw)): return null
    n = parseInt(trim(raw), 10); return (n > 0 && n <= 300) ? n : null
rateLimitMessage(headers, mode):                                  // :169-179
    secs = retryAfterSeconds(headers)
    if secs !== null && headers.get('x-should-retry') !== 'false':
        return `Rate limited \u2014 try again in about ${secs} second${secs === 1 ? '' : 's'}.`
    return mode === 'federated' ? FED_LIMIT : KEY_LIMIT
```

`FED_LIMIT`:

```text
Claude is unavailable: your organization's rate limit or spending cap has been reached. Retrying will not help \u2014 this needs whoever administers your organization\u2019s Anthropic account.
```

(The first `organization's` uses an ASCII apostrophe, the second `organization\u2019s` uses U+2019; both are REQUIRED byte-exact.)

`KEY_LIMIT`:

```text
Claude is unavailable: your account's rate limit or spending cap has been reached. Retrying will not help \u2014 check the limits and billing on your Anthropic account.
```

The predicate is headers-only (Anthropic publishes no distinct error type for an exhausted cap); a bare 429 is treated as limit-reached; an HTTP-date `Retry-After`, `0`, negative, `301`, `12.5` and non-numeric values are all "not usable"; the bound is inclusive at 300 and exclusive at 0; the wording never claims WHICH limit was hit; the party who can act depends on the mode. `x-should-retry` is compared case-sensitively to the exact string `false`. ### 2.13 Pre-egress preparation

`ensureFlattened` (`sop-prepare.ts:29-74`) is 04's (spec 04, 2.19). This subsystem's use: it runs before EVERY estimate, over the renderer's current `steps` (including `aiInserted` ones, which are text and skipped), so a step lacking a current marker-baked render is flattened and persisted first; the Claude path then reads only renders or plain shots through the gate. A shot is skipped when it already has `flattened` AND a truthy `markerBaked`, or when its `screenshot` is empty (the gate then refuses it with `Step ${n} has no readable screenshot.`). A failure message is `` `Step ${shotNo} ("${caption}") couldn't be prepared: ${message}` `` where `caption` is `trim(step.caption ?? '')` or the literal `untitled` when that is empty (`sop-prepare.ts:66-70`), and stops the run; an `AbortError` (the Cancel) is rethrown unwrapped and swallowed by the panel. Generation does NOT re-run it after the review (nothing can change in between: the dialog is modal). REQUIRED.

## 5. Edge cases and hard-won fixes

**EDGE-SOP-1. A project whose first item is a text block.** Its first screenshot is step 2. Required: prompt paragraph 3 and the header say so; apply lands `stepNumber: 2` and rejects `1`. Origin: #108 (`76b1ad6`). Citation: `claude-service.ts:184-191`, `sop-landing.test.ts:113-143`.

**EDGE-SOP-2. The model returns `steps: []`.** Constrained decoding with `minItems: 1` should prevent it; if it still arrives (the SDK parse rejects it inside `finalMessage`), the user sees `incompleteSopMessage(false)`, never a raw zod dump. Origin: #108. Citation: `claude-service.ts:561-575`.

**EDGE-SOP-3. A duplicate `stepNumber` whose later entry is empty.** `[{1,'Click Save'}, {1,'',''}]`: last wins, nothing lands, and the diagnosis is "wrote no step content" (not "numbered against steps that do not exist"). Origin: #111 (`44a8762`, found by macOS `fix/guard-matches-last-wins`). Citation: `sop-apply.ts:225-234`, `sop-landing.test.ts:210-240`. The reverse (`[{1,''}, {1,'Click Save'}]`) lands (macOS `testADuplicateWhoseSurvivingEntryHasContentIsAccepted`).

**EDGE-SOP-4. A plan that matches a step but carries only whitespace.** Does not land (`trim`). Citation: `sop-apply.ts:202`, `sop-landing.test.ts:145-152`.

**EDGE-SOP-5. A partial miss.** `[2 ok, 3 ok, 99]` over `[text, shot, shot]` lands 2 and logs `1 of 3 plan entries landed on no screenshot`. Required: success. Citation: `sop-landing.test.ts:164-181`, `claude-service.ts:627-631`.

**EDGE-SOP-6. A step with no `kind` key.** Normal on-disk shape for captured shots; it is a shot. A predicate written `kind === 'shot'` lands nothing. Citation: `sop-landing.test.ts:202-208`.

**EDGE-SOP-7. The refusal fixture must have an EMPTY body.** A test streaming a non-empty refusal cannot catch a reorder of `responseFailure`. Origin: macOS finding, #112 (`8fd71ef`). Citation: `claude-error-messages.test.ts:117-126`.

**EDGE-SOP-8. Truncated JSON at the output limit.** The SDK parse rejects inside `finalMessage` before `stop_reason` is readable from the final message, so the stop reason is captured from `message_delta` and the catch maps it to `CUTOFF_MSG`. Required natively: track `stop_reason` from `RawMessageDeltaEvent` and classify before parsing. Citation: `claude-service.ts:507-511`, `:536-538`, `:560`.

**EDGE-SOP-9. Malformed JSON or a non-empty schema violation with `end_turn`.** Electron surfaces the SDK's raw text because the SDK parse rejects first (an `AnthropicError`, not an `APIError`) and `friendlyError` falls through to `e.message`; the intended `Claude returned malformed SOP data. Please try again.` is unreachable. Measured against the installed SDK, the parser double-wraps the helper's error: malformed JSON reads `Failed to parse structured output: Error: Failed to parse structured output as JSON: <JSON.parse message>`, and a schema violation reads `Failed to parse structured output: Error: Failed to parse structured output: <zod issues as pretty-printed JSON>` followed by `\nValidation issues:\n  - <path>: <message>` (at most 5 issues). The TS SDK parses EVERY text block, so a second non-JSON text block fails a run whose first block was valid. Required natively: IMPROVEMENT D-SOP-1 (show the intended message; parse the first text block only). Citation: `claude-service.ts:559-588`, TS `helpers/zod.js:25-44`, `lib/parser.js:29-65`.

**EDGE-SOP-10. A refusal that arrives with an empty text block.** In Electron the SDK parse runs on the empty text before `responseFailure`, so the user sees `Failed to parse structured output: Error: Failed to parse structured output as JSON: Unexpected end of JSON input` (measured), not the refusal message. The same happens to a refusal that carries non-JSON text. Only a refusal with NO text block at all reaches `responseFailure` and shows `REFUSAL_MSG`. Required natively: IMPROVEMENT D-SOP-2 (classify first). Citation: `claude-service.ts:549-557`, TS `lib/parser.js:29-65`.

**EDGE-SOP-11. A regenerate after an author edited a caption.** The edited caption is sent (flag set); Claude's new caption clears the flag; a blank reply keeps the human text and the flag. Origin: #62 gap 3 (`207eddd`). Citation: `sop-input.ts:180-212`.

**EDGE-SOP-12. A regenerate when the overview is Claude's own from the last run.** The pre-AI backup overview is sent (often none), never Claude's text under "the author already wrote this overview". Origin: #79 (`9de16c3`); the first fix used `??` and was wrong. Citation: `sop-input.ts:83-104`.

**EDGE-SOP-15. A whitespace-only `plan.intro`.** `{ heading: ' ', body: '' }` is truthy, so the unflagged path stores `{ heading: ' ', body: '' }`; the codec's `coerceIntro` keeps it (it drops only both-empty) (01). Required: parity. Citation: `sop-apply.ts:142-143`.

**EDGE-SOP-20. Steps added after the first generation.** They are absent from the backup, so from the second regenerate on, `captionForPrompt` sends Claude's own previous caption for them (compounding). Required: parity (Q-SOP-6). Citation: `claude-service.ts:340-342`, `sop-input.ts:185`.

Because `ApiKeyExplicit` and `AuthTokenExplicit` are both true, the SDK skips environment and profile auto-resolution (`AnthropicClient.cs:170-212`); in federated mode `UsingTokenCredentials` is true and `BeforeSend` strips any env-derived key header and sets `Authorization: Bearer` from the SDK `TokenCache` (proactive refresh, one force-refresh-and-retry on 401; `AnthropicClient.cs:421-456`, `:499-541`). The client is disposed after each operation (`using`). Verified disposal semantics (resolving Q-SOP-17): `AnthropicClient.Dispose` disposes the `TokenCache` it created around `Credentials` (`_ownsCredentials`, `AnthropicClient.cs:149-157`, `:236-244`) and then calls `ClientOptions.DisposeHttpResources`, which ALWAYS disposes the `HttpClient` it was given, either directly or through `HttpClientPassthroughHandler.Dispose` (`ClientOptions.cs:368-380`, `HttpClientPassthroughHandler.cs:33-40`). So a shared `HttpClient` must never be assigned to `ClientOptions.HttpClient`; each client gets a fresh `new HttpClient(SharedHttp.Handler, disposeHandler: false)`, whose disposal leaves the shared handler chain alive. `WorkloadIdentityCredentials` disposes its exchange `HttpClient` only when it created it (`_ownsHttpClient`, `WorkloadIdentityCredentials.cs:41-50`, `:192-198`), so `SharedHttp.Exchange` may be shared. Do not use `ClientOptions.Handlers` for the pin and capture handlers: a `DelegatingHandler` can be attached to one chain only (`ClientOptions.cs:69-88`, `:340-343` throw `Handler is already attached to a client`), which a per-call client would violate on the second call. Consequence of a per-call client: its `TokenCache` lives for one operation, so the estimate and the generation each perform one token exchange (parity: Electron also builds a new provider per `makeClient`). Timeout semantics: `ExecuteOnce` disposes its timeout source when the response HEADERS arrive (`AnthropicClient.cs:600-664`), so `Timeout` bounds connect, send and time to first byte, never the length of a stream (the TS SDK behaves the same); a stalled open stream is Q-SOP-11. In API-key mode with `ANTHROPIC_PROFILE` set in the environment, the SDK writes a one-time shadowing warning to `Console.Error` (`AnthropicClient.cs:216-233`); harmless in a WPF process (no console).

**Handler chain** (`SharedHttp.Handler`, created once per process): `EgressPinHandler` -> `ResponseHeaderCaptureHandler` -> `SocketsHttpHandler { AutomaticDecompression = DecompressionMethods.All, UseProxy = true, DefaultProxyCredentials = CredentialCache.DefaultCredentials }` with the default proxy (`HttpClient.DefaultProxy`: on Windows it reads `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` environment variables FIRST and only then the user's system proxy settings, including WPAD/PAC; Q-SOP-20) and the default certificate validation (the Windows certificate store). `DefaultProxyCredentials` lets an integrated-auth corporate proxy authenticate as the signed-in Windows user, which Chromium did implicitly for the exchange (recommendation; spec 11 or 12 may own the shared stack). `SharedHttp.Exchange = new HttpClient(SharedHttp.Handler, disposeHandler: false)` for the WIF exchange, which calls `HttpClient.SendAsync` directly and so never passes through the SDK's own chain (`WorkloadIdentityCredentials.cs:114-116`). Every `HttpClient` here has `Timeout = Timeout.InfiniteTimeSpan` (the SDK owns timeouts; the exchange runs inside the API attempt's `BeforeSend` and inherits its timeout).

- `EgressPinHandler : DelegatingHandler` (IMPROVEMENT D-SOP-16): throws `InvalidOperationException("Refusing to contact a host other than api.anthropic.com.")` unless `request.RequestUri.Scheme == "https" && Host == "api.anthropic.com" (OrdinalIgnoreCase) && Port == 443`. ### 7.13 Threading, cancellation, disposal, persistence

- UI thread: view models and views only. `ClaudeService`, the assembler, the wire mapper and the consumer run on the thread pool after their first await (`ConfigureAwait(false)`). Progress returns through `Progress<T>` (11).
- Cancellation: every public async method takes a `CancellationToken`; user cancel surfaces as `OperationCanceledException`, which the view model swallows (INV-SOP-22). A cancellation after `GenerateAsync` returned has no effect (the apply is atomic and quick).
- Disposal: `AnthropicClient` per operation in a `using` (7.6); `CancellationTokenSource`s disposed in `finally`; the header capture scope is `IDisposable` (restores the previous `AsyncLocal` value).
- Persistence: settings through 10; project changes only through `ProjectSession` (7.9) and 04's flattener; nothing else is written.
- Settle (INV-SOP-28): `IProjectSettle.WhenSettledAsync(path, ct)` completes when the open session for `path` has `PendingCount == 0` (01 must expose it on `ProjectSession`, for example a `WhenIdleAsync()` task; request recorded in section 10). With no open session it completes immediately.

## 11. Open questions and risks

**Q-SOP-1. Is the Sonnet 5 price right?** Electron (and macOS) price `claude-sonnet-5` at USD 3 and 15 per million input and output tokens; Anthropic's current published table as cached in developer tooling (2026-06-24) lists USD 2 and 10. The estimate would overstate by 50 percent. Recommended default: keep `3` and `15` for parity until someone confirms the price on anthropic.com/pricing, then change it on all three platforms in one coordinated PR.

**Q-SOP-2. The estimate omits the output schema and thinking.** `count_tokens` counts `system` and `messages` only, so the structured-output grammar prompt is not counted. Recommended default: parity; revisit together with Q-SOP-1.

**Q-SOP-3. The root schema description `{$schema: "https://json-schema.org/draft/2020-12/schema"}`.** It is an artifact of the TS helper relocating zod's `$schema`, and it is sent to the model as prose. Recommended default: reproduce it byte-equal (parity of what the model sees); drop it on both Windows builds together later if desired.

**Q-SOP-4. Revert is wholesale in Electron, selective on macOS.** Steps added after generation are lost by Electron's revert; macOS keeps them. Recommended default: Electron parity for 2.0 (the confirm text promises "restore the project as it was before generation"), and raise a cross-platform issue.

**Q-SOP-5. Provenance names the first generation.** After a regenerate, `Generated with ... \u00B7 <time>` still shows the first run. Recommended default: parity; a "last generated" field would be a `project.json` contract change.

**Q-SOP-6. Steps added after the first generation compound.** They have no pre-AI original (EDGE-SOP-20). Recommended default: parity; a fix needs a contract change (per-step original caption) agreed with macOS.

**Q-SOP-7. Answer to 04's Q-EDIT-10.** Recommended default: a merged caption keeps `captionEditedByUser` (it is the human's structural decision and gives Claude both captions).

**Q-SOP-8. Long SDK waits on `Retry-After`.** Both SDKs honor any `Retry-After` before retrying (C# up to `int.MaxValue` ms). Recommended default: parity of SDK defaults plus the Cancel button (D-SOP-8). If pilots report long hangs, strip `Retry-After` values over 60 s in `ResponseHeaderCaptureHandler` AFTER capturing them (the SDK then uses 0.5 to 8 s backoff).

**Q-SOP-9. No image count, size or dimension check.** Very large or very many screenshots fail as an API 400 with the API's own text (row 14 of 7.12). Recommended default: parity; verify the current Messages API per-image and per-request limits and consider a pre-check with a friendly message later.

**Q-SOP-10. The tour mentions Claude with the switch off.** 06 owns the tour. Recommended default: parity (the switch defaults on, and the tour runs at first launch).

**Q-SOP-11. No idle timeout on a stalled stream.** Recommended default: none; Cancel (D-SOP-8) is the remedy.

**Q-SOP-12. `The 1 steps below`.** Recommended default: parity (changing prompt text changes model behavior and cache keys; do it on all platforms at once if at all).

**Q-SOP-13. The Home `SOP ready` badge with the switch off.** It describes project state, not a Claude action. Recommended default: keep (06).

**Q-SOP-14. The `Anthropic` package in ShotAI.Core.** It is platform-neutral and keeps the request, stream and error tests on Linux. Recommended default: reference it from Core; if PLAN.md forbids third-party packages in Core, move `Transport` to a new `ShotAI.Core.Claude` project (still `net10.0`) rather than to Platform.

**Q-SOP-15. Where the auth subsystem is specified.** Spec 01 names it "08 Auth", specs 03, 05 and 06 give 08 to brand and 06 folds auth into 07. This spec fixes the decision rule and interfaces but did not extract `src/main/entra/*` or `src/main/secrets.ts` end to end. Recommended default: PLAN.md adds a dedicated auth spec (MSAL WAM, cache extension, policy key and ADMX, DPAPI key store, the diagnostic exchange and its wording) and keeps 07's interfaces as its contract.

**Q-SOP-16. The flatten error's step number.** `Step ${shotNo}` counts shots, the gate counts all steps (EDGE-SOP-19). Recommended default: parity; if changed, change 04's flattener to the SOP number on all platforms.

**Q-SOP-17. `AnthropicClient` disposal and the shared `HttpClient`.** RESOLVED by verification against the SDK source (7.6): `Dispose` always disposes the `ClientOptions.HttpClient`, so each per-call client gets its own `new HttpClient(SharedHttp.Handler, disposeHandler: false)` and the shared handler chain survives. One client per credential identity remains a valid later optimization (it would also keep the `TokenCache` across the estimate and the generation, saving one exchange).

**Q-SOP-18. Should the estimate stop sending images?** Raised and deliberately not changed in #103 (a local approximation would be an estimate of an estimate). Recommended default: keep sending them, with the honest wording.

**Q-SOP-19. Optimistic apply vs a refused disk run.** With the apply as a `ProjectOperation`, a disk run that refuses (the disk differed from memory) rolls back after the user briefly saw the result. Recommended default: accept (it requires an external writer, which the single-instance rule makes rare), and show `SopMessages.Incomplete` with 05's notice.

**Q-SOP-20. `HttpClient.DefaultProxy` honors proxy environment variables on Windows.** .NET reads `HTTPS_PROXY`, `HTTP_PROXY` and `ALL_PROXY` before the user's system proxy settings (Microsoft Learn, "Make HTTP requests with the HttpClient class", Configure an HTTP proxy), while Chromium's stack (Electron's exchange path) uses only the system settings. A poisoned `HTTPS_PROXY` cannot read the traffic (TLS is still validated against the Windows store) but can observe or block it, and it is the same class of environment input INV-SOP-1 refuses for the base URL. Recommended default: set `SocketsHttpHandler.Proxy` explicitly to a system-settings-only proxy (for example one built from `WinHttpGetIEProxyConfigForCurrentUser` in ShotAI.Platform and injected into Core as an `IWebProxy`), so environment variables are ignored; decide with spec 11 or 12, which may own the shared HTTP stack.

**Q-SOP-21. A `ProjectOperation` that throws on the clone run.** Spec 01's `ProjectSession.Apply` table covers only `Changed` and `Unchanged`. `ApplySopPlanOperation` (no landing) and `RevertSopOperation` (nothing to revert) throw by design. Recommended default: 01 specifies that a throw on the clone leaves `Current` untouched, queues nothing, raises nothing, and faults the returned task with the original exception (7.9); until 01 confirms, the view model may run the operation on a clone itself before calling `Apply`.
