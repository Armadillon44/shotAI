## 2. Reference behavior (Electron)

### 2.1 Folder layout

**Projects root.** A user-chosen folder, default `path.join(app.getPath('home'), 'shotAI Projects')` (`src/main/settings.ts:129-131`), that is `%USERPROFILE%\shotAI Projects` on Windows. It holds one subfolder per project and nothing else the app reads. REQUIRED.

**Project folder** (`src/main/project-store.ts:302-309`, `src/main/archive.ts:4-10`):

```
<projects root>\<uuid>\            folder name = manifest id at creation, lowercase v4 UUID, never renamed
  project.json                     the manifest (this spec)
  project.json.<pid>.tmp           transient: atomic-write sibling (2.11); normally absent
  shots\                           original captures and imported images
    step-0001.png ...              capture writes step-NNNN.png (4-digit, 1-based; 02 owns), importStep writes step-NNNN.png or .jpg
  export\                          generated exports (09) and the render cache
    .render\<stepId>.png           flattened render per step (04 owns the content)
  archive.zip                      present only while archived (2.9.13)
  archive.zip.tmp                  transient during pack
```

- `createProject` and `createProjectFromImport` create `shots\` and `export\` empty (`src/main/project-store.ts:308-309,353-354`). REQUIRED.
- The header comment in `src/shared/project.ts:6` says `step-001.png`. That is stale: every writer uses four digits (`src/main/CaptureController.ts:1372`, `src/main/project-store.ts:1068`). REQUIRED: four digits. The same comment's `<projects-dir>/<Project Name>/` (`src/shared/project.ts:4`) is also stale: folders are named by the UUID (`src/main/project-store.ts:304-307`).
- Archiving then restoring a project whose `shots/` or `export/` held no files does not recreate that folder (the zip holds file entries only for files, and restore creates only the parents of written files, `src/main/archive.ts:39-40,126`). Capture recreates `shots/` before writing (`src/main/CaptureController.ts:696`) and `importStep` does too (`src/main/project-store.ts:1056`), so this is harmless. REQUIRED: every native writer that targets `shots/` or `export/` creates the folder first.
- A folder under the root counts as a project only if it has a readable `project.json` (`src/main/project-store.ts:491-499`).
- The human title lives only in the manifest. Two projects may share a title. Renaming never moves the folder (`src/main/project-store.ts:304-307,517-519`). REQUIRED.
- macOS writes `shots/import-<uuid>.<ext>` for imported images (`macOS:Packages/ShotModel/Sources/ShotModel/ProjectStore.swift:641`). The native reader must accept any file name that the manifest references; only this build's writers use `step-NNNN`.

### 2.5 Field coercions in detail

#### 2.5.1 `clampScale` (displayScale)

`src/shared/doc-scale.ts:44-56`. Constants: `SCALE_MIN 0.65`, `SCALE_MAX 1.25`, `SCALE_STEP 0.05`, `SCALE_DEFAULT 1`.

```
clampScale(value):
  n = (typeof value === 'number') ? value : NaN
  if n is not finite: return 1
  pct      = JsRound(n * 100)            // IEEE double multiply, then JS Math.round
  clamped  = min(125, max(65, pct))
  snapped  = JsRound(clamped / 5) * 5
  return snapped / 100                   // IEEE double divide
```

`JsRound(x)` is ECMAScript `Math.round`: the integer closest to x, and when x is exactly halfway, the one closer to +infinity (`Math.round(2.5) = 3`, `Math.round(-2.5) = -2`). It is NOT banker's rounding. Legal outputs are the 13 detents `0.65, 0.7, 0.75, 0.8, 0.85, 0.9, 0.95, 1, 1.05, 1.1, 1.15, 1.2, 1.25` (`doc-scale.ts:26-34`).

| Input | Output | Written |
|---|---|---|
| absent, `null`, `"banana"`, `true`, `{}` | 1 | omitted |
| `1`, `1.0`, `0.99`, `1.02` | 1 | omitted |
| `0.8` | 0.8 | `0.8` |
| `0.825` | 0.85 (`0.825 * 100` is exactly `82.5` in IEEE double, rounds to 83; `83 / 5 = 16.6` rounds to 17; `85 / 100`) | `0.85` |
| `0.675` | 0.7 (`67.5` to 68, `13.6` to 14, 70) | `0.7` |
| `1.025` | 1 (`1.025 * 100` is `102.49999999999999`, rounds to 102; `20.4` to 20; 100) | omitted |
| `9` | 1.25 | `1.25` |
| `0.1`, `-3` | 0.65 | `0.65` |

REQUIRED (Electron clamps in the codec). The macOS app stores the raw number and clamps at use; see conformance case `display-scale-out-of-range` (`open`, Armadillon44/shotAI_MacOS#105) and Q-MODEL-1.

### 2.6 normalizeSteps

`src/main/project-store.ts:68-98`:

```
normalizeSteps(steps):
  if (!Array.isArray(steps)) return []
  kept = []; dropped = 0
  for s of steps:
    if (typeof s !== 'object' || s === null || Array.isArray(s)) { dropped++; continue }
    kept.push({ ...s, annotations: Array.isArray(s.annotations) ? s.annotations : [] })
  if (dropped > 0) projectsLog.error(`manifest: dropped ${dropped} malformed step(s) of ${steps.length}`)
  return kept
```

- Dropped: `null`, numbers, strings, booleans, arrays. Kept: every object, including `{}` (it becomes `{"annotations": []}`), and objects with wrong-typed fields.
- The spread keeps the step's own keys in JS order. If `annotations` existed it keeps its position (its value is replaced with `[]` when not an array); if it did not exist it is appended as the LAST key.
- History: a `null` element used to throw on `step.annotations`, which failed the open AND removed the project from Home (#86, fixed in `bb0decc` / #97). Non-object junk used to survive as a ghost step and is now dropped. REQUIRED.

### 2.7 The writer: exact bytes

`writeManifest` writes `JSON.stringify(manifest, null, 2)` through `writeFileAtomic` as UTF-8 (`src/main/project-store.ts:232-240`, `src/main/atomic-write.ts:44`). REQUIRED byte format:

| Property | Rule |
|---|---|
| Encoding | UTF-8, no BOM |
| Newlines | `\n` only |
| Trailing newline | none; the file ends with `}` |
| Indent | 2 spaces per level |
| Object | `{` newline, then each member as `<indent>"key": value` joined by `,\n`, then newline, `<outer indent>}`. Empty object: `{}` |
| Array | `[` newline, elements joined by `,\n`, newline, `]`. Empty array: `[]` |
| Separator | `": "` (colon, one space) |
| Strings (keys and values) | escape `"` as `\"`, `\` as `\\`, U+0008 `\b`, U+0009 `\t`, U+000A `\n`, U+000C `\f`, U+000D `\r`; any other code unit below U+0020 as `\u00xx` with LOWERCASE hex; a lone surrogate code unit (high not followed by low, or low not preceded by high) as `\udxxx` lowercase; EVERYTHING ELSE LITERAL, including `/`, `<`, `>`, `&`, `'`, U+007F, U+2028, U+2029, all non-ASCII and unassigned code points |
| Numbers | ECMAScript `Number::toString` (section 7.2.2): `1` not `1.0`, `0.85`, `1e+21`, `1e-7`, `100000000000000000000`; `-0` writes `0`; NaN and +/-Infinity write `null` |
| `undefined` | a key whose value is `undefined` is omitted (this is how `patch.callout = undefined` clears a callout, `ipc.ts:204-206`) |

**Key order.** `JSON.stringify` uses the object's own-key order, which in JS is: first every key that is an array index (a canonical decimal string of an integer 0 to 2^32-2, such as `"0"`, `"7"`, `"42"`, but not `"07"` or `"-1"`), in ascending numeric order; then every other string key in insertion order. Consequences:

1. After a decode (no mutation), the root order is: unknown keys (index-like first ascending, then the rest in their file order), then `version, id, title, createdWith, createdAt, updatedAt, captureSettings, steps, [displayScale], [theme], intro, [introEditedByUser], sopBackup, archived, archivedAt` (`manifest-extras.test.ts:206-222`). Call this the **canonical order**.
2. A key a mutation ADDS to an object that lacked it is appended last in that save: `setProjectIntro` appends `introEditedByUser` after `archivedAt`; `setProjectDisplayScale` and `setProjectTheme` append theirs; `createProject` writes `theme` after `archivedAt` (`project-store.ts:312-330`). The next read restores canonical order, so the file's key order changes between two saves without a user edit. This is known and filed as "the Windows twin of shotAI_MacOS#110" (`manifest-extras.test.ts:192-199`, `77adda3`).
3. Step key order is the order the step object had on disk (a spread), plus keys added by patches appended in patch order (`Object.assign`, `step-render.ts:22`).

The Electron source states key order is not part of the cross-platform contract (`project-store.ts:169-172`). macOS writes sorted keys (`macOS:Packages/ShotModel/Sources/ShotModel/ProjectJSON.swift:31-35`).

Example: a new default-branded project as Electron writes it (this is also canonical order):

```json
{
  "version": 1,
  "id": "0f8c2e1a-5b7d-4c3e-9a1f-2b3c4d5e6f70",
  "title": "Project 2026/09/22 14:03:07",
  "createdWith": "shotAI",
  "createdAt": "2026-09-22T19:03:07.123Z",
  "updatedAt": "2026-09-22T19:03:07.123Z",
  "captureSettings": null,
  "steps": [],
  "intro": null,
  "sopBackup": null,
  "archived": false,
  "archivedAt": null
}
```

### 2.8 JSON.parse semantics the codec relies on

`readManifest` = `fs.readFile(path, 'utf8')` then `JSON.parse` then `coerceManifest` (`src/main/project-store.ts:226-230`). These properties of Node and V8 decide what a file means and must be reproduced (section 7.2):

| Situation | Electron behavior |
|---|---|
| Invalid UTF-8 byte sequences | decoded to U+FFFD by `Buffer.toString('utf8')`, then parsed |
| UTF-8 BOM (EF BB BF) | kept as U+FEFF, which is not JSON whitespace: `JSON.parse` throws, project unreadable |
| Duplicate keys in one object | last value wins; the key keeps its FIRST position |
| `__proto__` key | becomes an ordinary own data key (JSON.parse uses CreateDataProperty) |
| All numbers | IEEE double; `1e400` parses to `Infinity` (and is then written as `null`); `12345678901234567890` loses precision to `12345678901234567000` |
| Lone surrogate escape `"\ud800"` | accepted, yields a string with a lone surrogate |
| Nesting depth | no fixed limit (V8 stack) |
| Comments, trailing commas, single quotes, NaN literals | rejected |
| Whitespace | only space, tab, LF, CR |

### 2.9 Store operations

#### 2.9.1 Known-project gate

`resolveKnownProject(projectPath)` (`src/main/project-store.ts:55-64`), run first by every operation that takes a project path (open, rename, reveal, delete, archive, unarchive, mutate, every step op, read-for-pipelines):

```
resolved = path.resolve(projectPath)
root     = path.resolve(settings.projectsDir)
rel      = path.relative(root, resolved)
if (rel !== '' && !rel.startsWith('..') && !path.isAbsolute(rel)) return resolved   // under root, ANY depth
if (settings.recents.some(r => path.resolve(r) === resolved)) return resolved       // exact string compare
throw new Error('Project path is not within the projects directory')
```

- On Windows, `path.win32.relative` compares case-insensitively; the recents compare is case-sensitive.
- `rel.startsWith('..')` also rejects a child literally named like `..foo` (safe false negative).
- The root itself is rejected (`rel === ''`).
- Rationale: stop a compromised renderer from reading arbitrary files. REQUIRED as defense in depth; its original threat (an untrusted renderer) is ELECTRON-ONLY (spec 11).

#### 2.9.2 The write queue

One module-level promise chain, `writeQueue`, shared by ALL projects (`src/main/project-store.ts:636-637`). Each queued op:

```
run = writeQueue.then(async () => { ...resolve, read manifest FROM DISK, modify, write... })
writeQueue = run.then(() => undefined, () => undefined)   // a rejection never breaks the chain
return run                                                 // the caller sees the result or the error
```

- FIFO in call order. Every op re-reads `project.json` from disk inside the job, so the disk is the source of truth and nothing is cached between ops.
- Queued: `renameProject`, `archiveProject`, `unarchiveProject`, `mutate` (and through it `setProjectDisplayScale`, `setProjectTheme`, `setProjectIntro`, SOP apply and revert), `addStep`, `updateStep`, `mergeSteps`, `deleteStep`, `deleteSteps`, `reorderSteps`, `addTextStep`, `insertStepAt`, `importStep`.
- NOT queued: `createProject`, `createProjectFromImport` (fresh folders), `loadProject`'s id back-fill write (`:395-398`), `deleteProject`, `listProjects`, `listRecentProjects`, `getProjectForRead`, `revealProject`. See EDGE-MODEL-23 and EDGE-MODEL-24.
- A thrown error inside the job aborts that op without writing (`mutate-serialize.test.ts:66-77`).
- The settings file has its own separate queue (`src/main/settings.ts:205-220`); recents updates go through it. It is a different chain from `writeQueue`, so a recents update never waits behind a manifest write and vice versa.

REQUIRED.

#### 2.9.5 List

#### 2.9.13 Archive, unarchive, auto-archive

**Zip format** (`src/main/archive.ts:1-134`): `archive.zip` at the project root holds every regular file under `shots/` and `export/` (recursively, hidden files and `export/.render/` included), with entry names relative to the project root using `/` (for example `shots/step-0001.png`, `export/.render/<id>.png`, `export/My Guide.html`). DEFLATE, level 6. JSZip also writes directory entries (`shots/`, `export/`, `export/.render/`) for parents; readers must skip directory entries. `project.json` and any other root file are never included or touched. Symlinked entries (Dirent neither file nor directory) are skipped.

**packArchive(dir)** (`archive.ts:59-102`):

1. If `archive.zip` exists: return (no-op).
2. Collect files (`walkFiles`, `:26-42`); a missing dir contributes nothing.
3. Build the zip in memory.
4. Write `archive.zip.tmp`; re-read it; `got` = sorted non-directory entry names, `want` = sorted collected names; if the lengths or any name differ throw `` `archive verification failed (${got.length} entries, expected ${want.length}) \u2014 nothing deleted` `` after removing the tmp.
5. `fs.rename(tmp, archive.zip)` (no retry).
6. Only now `fs.rm(shots, recursive, force)` and `fs.rm(export, ...)`.
7. Log `` `archive: packed ${files.length} file(s) \u2192 ${zipPath}` ``.

A project with zero files still produces an (empty) `archive.zip` and becomes archived.

**unpackArchive(dir)** (`archive.ts:110-134`):

1. If no `archive.zip`: return.
2. Load the zip. For each NON-directory entry: `rel = name.replace(/\\/g, '/')`; allowed iff `rel === 'shots' || rel === 'export' || rel.startsWith('shots/') || rel.startsWith('export/')`, else throw `` `archive contains an unexpected path: ${e.name}` ``; `abs = confinePathNoSymlinks(dir, rel)`, else throw `` `refusing to extract a path outside the project: ${e.name}` ``; `mkdir -p`; `writeFile(abs, bytes)` (overwrites).
3. `fs.access` every written file; then `fs.rm(archive.zip)`.
4. Log `` `archive: restored ${written.length} file(s) from ${zipPath}` ``.

A failure leaves `archive.zip` in place (and possibly some extracted files, which the next attempt overwrites).

### 2.10 Path confinement

**`confinePath(dir, rel)`** (lexical, `src/main/path-confine.ts:20-27`):

```
abs    = path.resolve(dir, rel)
within = path.relative(dir, abs)
if (within === '' || within.startsWith('..') || path.isAbsolute(within)) return null
return abs
```

Rejects: the folder root itself (`'.'`, `''`), any escape (`'../x'`, `'shots/../../x'`), an absolute path outside `dir`, a Windows path on another drive. An ABSOLUTE path that lands inside `dir` is accepted (the result is the same absolute path). Used for every READ of a manifest-sourced path: the `shot://` protocol, Claude and export reads, the OCR scan (`ipc.ts:539`). REQUIRED.

**`confinePathNoSymlinks(dir, rel)`** (`path-confine.ts:51-76`):

```
abs = confinePath(dir, rel); if (abs === null) return null
base = path.resolve(dir); tail = path.relative(base, abs); current = base
for component of tail.split(path.sep):
  if component === '': continue
  current = path.join(current, component)
  try { if ((await fs.lstat(current)).isSymbolicLink()) return null }   // FIRST link wins
  catch (e) { if (e.code === 'ENOENT') break; return null }             // missing: fine; any other error: refuse
return abs
```

- `dir` itself and its ancestors are NOT checked (the user's own layout).
- A link is refused even when its target is inside the project: the check is on the mechanism, because a link can be repointed between check and write (`path-confine-symlink.test.ts:56-63`).
- A regular FILE used as a directory component makes the next `lstat` fail with `ENOTDIR` on POSIX, which is refused. On Windows the same probe most likely fails with `ERROR_PATH_NOT_FOUND`, which libuv maps to `ENOENT`, so Electron BREAKS and returns the path, and the following write fails instead (UNVERIFIED on hardware). Either way nothing is written; native refuses on both platforms (7.5, `File` rule).
- A non-string `rel` makes `path.resolve` throw `TypeError [ERR_INVALID_ARG_TYPE]` (both functions); callers pass manifest values unchecked (EDGE-MODEL-50).
- On Windows, Node's `lstat` reports a directory junction as a symbolic link (confirmed on real hardware 2026-09-15 with `mklink /J %TEMP%\junc %TEMP%`, `path-confine.ts:62-68`).
- Used for every WRITE or DELETE: render write (`step-render.ts:54`), archive restore (`archive.ts:124`), package import (`project-store.ts:363`), step file delete (`:891`). Reads keep the lexical check, matching macOS (#82, `8f3941a`). REQUIRED. Two WRITES are NOT confined in Electron: capture's own shot write (`CaptureController.ts:1373-1377`; 02 decides) and `importStep`'s image write (`project-store.ts:1055-1069`, EDGE-MODEL-49; natively confined, D-22).

### 2.11 Atomic write

`src/main/atomic-write.ts:11-51`:

```
RENAME_RETRY_DELAYS_MS = [10, 25, 50, 100, 200, 350, 600]

renameWithRetry(from, to, onRetry?):
  for attempt = 0, 1, 2, ...:
    try { fs.rename(from, to); return }
    catch (e):
      code = e.code ?? ''
      retriable = code === 'EPERM' || code === 'EACCES' || code === 'EBUSY'
      if (!retriable || attempt >= 7) throw e
      if (attempt === 0) onRetry?.(code)
      sleep(RENAME_RETRY_DELAYS_MS[attempt])

writeFileAtomic(file, data, opts?):
  mkdir -p dirname(file)
  tmp = `${file}.${process.pid}.tmp`
  fs.writeFile(tmp, data, { encoding: 'utf8', mode: opts?.mode })   // no fsync
  try renameWithRetry(tmp, file, opts?.onRetry)
  catch (e) { fs.rm(tmp, {force: true}) (errors ignored); throw e }
```

- At most 8 rename attempts, 1335 ms of sleeping in total.
- `fs.rename` on Windows is `MoveFileExW(from, to, MOVEFILE_REPLACE_EXISTING)` (libuv).
- A failure of the tmp write itself does NOT remove the tmp.
- `mkdir -p` of the parent means writing a manifest into a deleted project folder recreates the folder.
- `writeManifest` passes no `onRetry`. The other callers (owned by 08 and 10, listed so the native `AtomicFile` API covers them):

| Caller | File | `mode` | `onRetry` log (verbatim, warn) | Citation |
|---|---|---|---|---|
| settings | `settings.json` | none | `` `settings rename ${code} \u2014 retrying (lock likely transient)` `` | `src/main/settings.ts:197-202` |
| secrets | `secrets.json` | `0o600` | `` `secrets rename ${code} \u2014 retrying (lock likely transient)` `` | `src/main/secrets.ts:36-44` |
| Entra token cache | `entra-cache.bin` (a Buffer; `encoding: 'utf8'` is ignored for a Buffer, so bytes round-trip exactly) | `0o600` | `` `entra cache rename ${code}, retrying` `` | `src/main/claude-auth.ts:48-55` |

- `mode` is applied by Node only on POSIX (on Windows it can only set the read-only attribute, and `0o600` leaves the file writable). ELECTRON-ONLY for this subsystem: native `AtomicFile` takes no mode; 08 decides how the secrets and token cache files are protected (DPAPI, per the fixed decisions).

**EDGE-MODEL-13.** Windows reparse points that are NOT links: OneDrive Files On-Demand placeholders (cloud reparse tags), deduplicated files, and similar. Node's `lstat` reports only symlink and junction tags as links, so the no-symlink walk allows these (correct: they do not redirect the path). However libuv's `readdir` with file types reports ANY reparse point as a link (verify: libuv `src/win/fs.c`, `fs__scandir`), so Electron's `listProjects` would skip a project folder that is a cloud placeholder, and `walkFiles` would skip placeholder FILES from the archive and then delete them with `fs.rm`, a silent data loss if the projects root is inside a Files On-Demand folder. Required natively: treat only name-surrogate reparse tags as links everywhere; include cloud placeholders in listing and archiving, reading them fully (which hydrates them) and failing the archive closed if a read fails, as macOS does with a coordinated read (`macOS:Packages/ShotModel/Sources/ShotModel/Archive.swift:161-175`). Microsoft documents that "Most Windows applications see exposed placeholders by default" (the reparse point is visible through directory enumeration) and that Windows may disguise them for some applications for compatibility (Microsoft Learn, `RtlSetProcessPlaceholderCompatibilityMode`), so the concern applies to both Electron and a native process unless it disguises placeholders. Origin: analysis for this spec; the libuv `readdir` classification is unverified on hardware (Q-MODEL-6).

So `/^shots\/[^/]+$/` rejects `"shots/a.png\n"` in JS, while a naive .NET port accepts it. Required natively: every ported regex uses `\z` (and `[0-9]` for `\d`, since .NET `\d` matches every Unicode decimal digit and JS `\d` only ASCII). Citation: `project-store.ts:281,359,1062`.

**EDGE-MODEL-56.** Restoring an archive does not recreate an empty `shots/` or `export/` (2.1). Required: native writers create the folder before writing (capture, import, render); `UnpackAsync` MAY recreate both folders after a successful restore (IMPROVEMENT, harmless). Citation: `archive.ts:39-40,126`.

**EDGE-MODEL-57.** `importStep` writes the image before the manifest; a manifest write failure leaves an orphan `step-NNNN` file, which the next import's counter then skips past. Required: parity (the orphan is harmless and the counter design already tolerates orphans). Citation: `project-store.ts:1068-1091`.

**EDGE-MODEL-58.** Stale comments that a literal port could follow: `mergeSteps`'s doc comment says the merged step "stays at the DROPPED step's position", but the code splices the dropped step out and leaves the kept step in its own slot (`project-store.ts:798-799` versus `:824`); `conformance.test.ts:75-77` still says a `null` entry in `steps` makes `coerceManifest` throw, which #97 fixed. Required: follow the code, not the comments.

### 7.2 JSON with ECMAScript semantics

System.Text.Json's `JsonNode` tree is the in-memory representation (fixed decision). Two things it cannot do out of the box are added in Core: a reader that accepts what `JSON.parse` accepts, and a writer that emits what `JSON.stringify` emits.

#### 7.2.1 Reader: `JsJson.Parse`

```csharp
public static class JsJson
{
    /// Node readFile('utf8') + JSON.parse. Throws JsJsonException for text that is not JSON.
    public static JsonNode? Parse(ReadOnlySpan<byte> fileBytes);
    public static JsonNode? Parse(string text);
    public static string Stringify(JsonNode? value, int indent = 2);   // indent 0 = compact JSON.stringify(v)
    public const int MaxDepth = 1000;
}
```

Algorithm:

1. IMPROVEMENT: if the bytes start with `EF BB BF`, skip those three bytes (EDGE-MODEL-28).
2. Decode with `Encoding.UTF8.GetString` (replacement fallback, U+FFFD) and re-encode with `Encoding.UTF8.GetBytes`, so invalid sequences behave as in Node (EDGE-MODEL-29).
3. Tokenize with `Utf8JsonReader` (`JsonReaderOptions { CommentHandling = Disallow, AllowTrailingCommas = false, MaxDepth = 1000 }`). Build the tree iteratively (explicit stack, no recursion).
4. Strings and property names: if `reader.ValueIsEscaped`, unescape `reader.ValueSpan` with Core's own unescaper, which decodes `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t` and `\uXXXX` and KEEPS lone surrogates; otherwise `Encoding.UTF8.GetString(reader.ValueSpan)`. Never call `reader.GetString()` (it rejects lone surrogates) (EDGE-MODEL-30).
5. Numbers: `reader.TryGetDouble(out d)`; if that fails, `double.Parse(raw, NumberStyles.Float, CultureInfo.InvariantCulture)`, which yields +/-Infinity on overflow. Store `JsonValue.Create(d)`. Every number becomes a double, as in JS (EDGE-MODEL-32). (Microsoft Learn documents only that `TryGetDouble` returns false when the token cannot be parsed; whether it returns false or Infinity for `1e400` is not documented for the reader, so the fallback is required either way.) A tree holding a non-finite double must never be handed to a System.Text.Json serializer (`ToJsonString`, `JsonSerializer`), which rejects non-finite numbers by default; only `JsJson.Stringify` writes manifest trees.
6. Objects: when a property name already exists, replace its value in place (`obj[name] = value`), keeping the first position (EDGE-MODEL-31). Never call `JsonObject.Add` for a possibly duplicate key.
7. Any `JsonException` becomes `JsJsonException` with the reader's message.

The `MaxDepth` of 1000 is a bounded divergence from V8 (which has no fixed limit); deeper files are reported as corrupt.

#### 7.2.2 Writer: `JsJson.Stringify`

Hand-written text emission, not `Utf8JsonWriter`, because `Utf8JsonWriter` cannot produce `JSON.stringify`'s bytes: it escapes with uppercase hex, escapes code points its encoder does not know (unassigned or newer emoji), cannot emit a lone surrogate escape, formats numbers as .NET does (`1E+21`), and uses `Environment.NewLine` unless configured. The writer walks the `JsonNode` tree:

- Formatting exactly as 2.7 (indent 2, `": "`, `,\n`, `{}` and `[]` for empty containers, no trailing newline, LF).
- Own-key order of every object (`JsOrder.Keys(JsonObject)`): array-index keys (strings matching `^(0|[1-9][0-9]*)$` whose value is at most 4294967294) in ascending numeric order first, then the remaining keys in the object's insertion order.
- String escaping exactly per 2.7 (`QuoteJSONString`, ES2019 well-formed).
- Numbers: `JsNumber.ToJsString(double)`; non-finite writes `null`.
- `null` node writes `null`; booleans `true` and `false`.

`JsNumber.ToJsString(x)` implements ECMAScript `Number::toString(x)` for radix 10:

```
if x is NaN: return "NaN"; if x is +Infinity: return "Infinity"; if x is -Infinity: return "-Infinity"
   // JS String(x). The JSON writer never calls it for these (it emits null); ImportStepAsync's
   // file name does (String(Infinity + 1) is "Infinity", 2.9.12)
if x == 0 (including -0): return "0"
if x < 0: return "-" + ToJsString(-x)
r = x.ToString("R", CultureInfo.InvariantCulture)        // shortest round-trip digits (.NET Core 3.0+)
parse r into: digits s (no leading or trailing zeros, k = s.Length) and n, where x = 0.s * 10^n
  (for "123.45": s = "12345", n = 3; for "1E+21": s = "1", n = 22; for "1.5E-07": s = "15", n = -6; for "0.001": s = "1", n = -2)
if k <= n && n <= 21:  return s + new string('0', n - k)
if 0 < n && n <= 21:   return s[..n] + "." + s[n..]
if -6 < n && n <= 0:   return "0." + new string('0', -n) + s
e = n - 1; sign = e < 0 ? "-" : "+"
return (k == 1 ? s : s[0] + "." + s[1..]) + "e" + sign + Math.Abs(e)
```

`Decode` rules are the table in 2.2 applied to `JsonNode`. JS `typeof` maps as: `JsonValue` of kind Number is "number", String is "string", True or False is "boolean"; `JsonObject` and `JsonArray` are "object"; a JSON null or missing key is null or undefined. Decode must not mutate its input (the harness reuses fixture objects).

`NormalizeSteps`: for each element, `JsonObject` is kept (`DeepClone`), with `annotations` set to a new empty `JsonArray` in place when present and not an array, or appended when missing; any other element is dropped and counted; if any were dropped, log at Error `"manifest: dropped {dropped} malformed step(s) of {total}"`.

`Encode` emits, in this order: every extra (the writer applies JS own-key order, so index-like extras still come first overall), `version`, `id`, `title`, `createdWith`, `createdAt`, `updatedAt`, `captureSettings` (deep clone or null), `steps` (each `Raw` deep-cloned), `displayScale` if not null, `theme` if not null, `intro` (object `{heading, body}` or null), `introEditedByUser: true` if set, `sopBackup` (object `{steps, title, intro, [introEditedByUser], model, tone, at}` or null), `archived`, `archivedAt`.

`Confine(dir, rel)`:

1. If `rel` is null or empty, or `HasHostileSegment(rel)`, return null.
2. `baseFull = Path.GetFullPath(dir)`; `abs = Path.GetFullPath(Path.Combine(baseFull, rel))` (on Windows both `/` and `\` separate; `Path.Combine` returns `rel` when it is rooted, which reproduces `path.resolve`). Catch `ArgumentException`, `NotSupportedException`, `PathTooLongException` and return null.
3. `within = Path.GetRelativePath(baseFull, abs)` (case-insensitive on Windows, like `path.win32.relative`).
4. Return null if `within == "."`, or `within.StartsWith("..", StringComparison.Ordinal)`, or `Path.IsPathRooted(within)`; else `abs`.

`Path.GetFullPath` applies the same Win32 normalization that `CreateFileW` will apply (dot segments, trailing dots and spaces on the last segment), so the checked path is the opened path.

`HasHostileSegment(rel)` (Windows rules, applied on every platform so Linux tests cover them): true if `rel` contains `\0`, `:`, `*`, `?`, `"`, `<`, `>` or `|`, starts with `\\?\`, `\\.\`, `//?/` or `//./`, or any segment (split on `/` and `\`) ends with `.` or space (other than the exact segments `.` and `..`, which the lexical check handles), or any segment's name before its first `.` equals, case-insensitively, `CON`, `PRN`, `AUX`, `NUL`, `COM1` to `COM9`, `LPT1` to `LPT9`, or `COM` or `LPT` followed by U+00B9, U+00B2 or U+00B3. Consequence: an absolute `rel` with a drive letter is rejected even when it lands inside the folder, which Electron accepted; no shotAI writer produces one.

`ConfineNoLinks(dir, rel, probe)`:

```
abs = Confine(dir, rel); if null return null
baseFull = GetFullPath(dir); parts = GetRelativePath(baseFull, abs).Split(DirectorySeparatorChar)
current = baseFull
for i in 0..parts.Length-1:
    if parts[i] == "": continue
    current = Path.Join(current, parts[i])
    switch probe.Probe(current):
        Missing:   return abs                      // nothing deeper exists (ENOENT break)
        Link:      return null                     // first link wins
        Unknown:   return null                     // cannot tell is not safe
        File:      if i < parts.Length - 1 return null   // ENOTDIR parity
        Directory: continue
return abs
```

`ManagedPathProbe` (Core, used on Linux and in Core tests):

```
try { a = File.GetAttributes(p) }                          // does not follow the final link
catch (FileNotFoundException or DirectoryNotFoundException) { return Missing }
catch { return Unknown }
if (a has ReparsePoint):
    fsi = a has Directory ? new DirectoryInfo(p) : new FileInfo(p)
    try { return fsi.LinkTarget != null ? Link : (a has Directory ? Directory : File) }   // symlink, junction
    catch { return Unknown }
return a has Directory ? Directory : File
```

`WindowsPathProbe` (Platform, registered in the App): `FindFirstFileExW(p, FindExInfoBasic, ...)` through CsWin32, which returns the attributes and, when `FILE_ATTRIBUTE_REPARSE_POINT` is set, the reparse tag in `WIN32_FIND_DATAW.dwReserved0` without opening or hydrating the file. `ERROR_FILE_NOT_FOUND` or `ERROR_PATH_NOT_FOUND` is `Missing`; any other failure is `Unknown`. A reparse point whose tag has the name-surrogate bit (`(tag & 0x20000000) != 0`: symlink `0xA000000C`, mount point or junction `0xA0000003`, and other surrogates) is `Link`; any other tag (cloud placeholders `0x9000xxxA`, dedup, AppExecLink) is classified by the directory attribute (EDGE-MODEL-13). `FindFirstFileExW` treats `*` and `?` as wildcards and misbehaves on a trailing separator; `ConfineNoLinks` never passes either, because `HasHostileSegment` rejects wildcard characters and the walk joins components without a trailing separator. NativeMethods.txt: `FindFirstFileExW`, `FindClose`, `WIN32_FIND_DATAW`, `FINDEX_INFO_LEVELS`, `FINDEX_SEARCH_OPS`.

**Reparse-safe traversal** (INV-MODEL-33): `ReparseSafeDelete.DeleteTree(string path, IPathProbe probe)` walks with `Directory.EnumerateFileSystemEntries` one level at a time; for an entry probed as `Link`, delete the link itself (`Directory.Delete(entry, recursive: false)` for a directory link on Windows, where `RemoveDirectory` removes a junction or directory symlink without touching the target; `File.Delete` for a file link, and on Linux for any symlink, since `unlink` removes a symlink whatever it points to; which .NET call removes a directory symlink on Linux is UNVERIFIED, so the Linux test pins it) and never descend; for a directory, recurse, then delete it; clear `ReadOnly` on files before deleting (Node's `fs.rm` removes read-only files on Windows). A missing path is fine (`force: true`). The archive walk and the root listing use the same probe to skip links. Do not rely on `Directory.Delete(path, true)`'s own reparse handling; the explicit walk is what the test pins.

### 7.6 Atomic file

```csharp
public interface IRenameRetryClassifier
{
    /// "EPERM", "EACCES" or "EBUSY" when the failure is a transient lock; otherwise null.
    string? Classify(Exception ex);
}

public sealed class AtomicFile(TimeProvider time, IRenameRetryClassifier classifier)
{
    // Not `[10, 25, ...].Select(...)`: a collection expression has no natural type, so
    // calling an extension method on one does not compile.
    public static readonly TimeSpan[] RenameRetryDelays =
        new[] { 10, 25, 50, 100, 200, 350, 600 }.Select(ms => TimeSpan.FromMilliseconds(ms)).ToArray();

    public Task WriteAsync(string file, ReadOnlyMemory<byte> data, Action<string>? onRetry = null, CancellationToken ct = default);
    public Task RenameWithRetryAsync(string from, string to, Action<string>? onRetry = null);
}
```

`WriteAsync`:

1. `Directory.CreateDirectory(Path.GetDirectoryName(file)!)` (parity: `mkdir -p`; see EDGE-MODEL-24 for why deletes are queued).
2. `tmp = $"{file}.{Environment.ProcessId}.tmp"` (parity). Safe because every write of a given file is serialized (7.7) and the app is single-instance (03).
3. Write with `new FileStream(tmp, FileMode.Create, FileAccess.Write, FileShare.None, 4096, FileOptions.Asynchronous)` (`FileMode.Create` truncates a leftover tmp, as Node's `'w'` flag does), `await fs.WriteAsync(data, ct)`, `await fs.FlushAsync(ct)`, then `fs.Flush(flushToDisk: true)` (synchronous; there is no async overload with `flushToDisk`) and dispose (IMPROVEMENT: `FlushFileBuffers` before the rename so a power loss cannot leave a renamed but empty file; Q-MODEL-5). On any write failure delete the tmp and rethrow (IMPROVEMENT, EDGE-MODEL-22).
4. `RenameWithRetryAsync(tmp, file, onRetry)`; on final failure delete the tmp (ignore errors) and rethrow.

`ct` is honored only before step 3 begins; a started write always completes.

`RenameWithRetryAsync`: `for attempt = 0..7`: `File.Move(from, to, overwrite: true)` (on Windows this is `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING`, the flag libuv uses; the .NET runtime also passes `MOVEFILE_COPY_ALLOWED`, which is inert for a same-directory rename; UNVERIFIED against the runtime source for .NET 10); on exception, `code = classifier.Classify(ex)`; if `code is null || attempt >= 7` rethrow; if `attempt == 0` invoke `onRetry(code)`; `await Task.Delay(RenameRetryDelays[attempt], time)`.

`WindowsRenameRetryClassifier` (Platform) maps the Win32 error in `ex.HResult` (when `(HResult >> 16) == 0x8007`, code = `HResult & 0xFFFF`), following libuv's mapping (verify against libuv `src/win/error.c` when implementing):

| Win32 error | libuv code | Classified |
|---|---|---|
| `ERROR_ACCESS_DENIED` (5), surfaced as `UnauthorizedAccessException` | EPERM | `"EPERM"` |
| `ERROR_SHARING_VIOLATION` (32) | EBUSY | `"EBUSY"` |
| `ERROR_LOCK_VIOLATION` (33) | EBUSY | `"EBUSY"` |
| `ERROR_NOACCESS` (998), `ERROR_CANT_ACCESS_FILE` (1920) | EACCES | `"EACCES"` |
| anything else | | null |

The managed default (Core, Linux) classifies `UnauthorizedAccessException` as `"EACCES"` and an `IOException` whose message or HResult indicates EBUSY as `"EBUSY"`. Tests inject a fake classifier and a `FakeTimeProvider` (NuGet `Microsoft.Extensions.TimeProvider.Testing`) so the schedule is asserted without sleeping.

### 7.7 The write queue

```csharp
public sealed class SerialWriteQueue : IDisposable, IAsyncDisposable
{
    public Task<T> Enqueue<T>(Func<CancellationToken, Task<T>> job, CancellationToken ct = default);
    public Task DrainAsync(TimeSpan timeout);      // IMPROVEMENT: used at app exit
}
```

The same type backs `SettingsService`'s own queue (10 7.4.3); the two queues are independent (ARCHITECTURE 6.1).

- One instance per `ProjectStore`, shared by all projects (parity: one global chain).
- Implementation: an unbounded `Channel<WorkItem>` with `SingleReader = true` and one consumer loop started at construction; each `WorkItem` holds the job and a `TaskCompletionSource<T>` created with `TaskCreationOptions.RunContinuationsAsynchronously`; because `Enqueue<T>` is generic and the channel is not, the channel carries a non-generic abstract `WorkItem` with `abstract Task RunAsync()`, implemented by a private `WorkItem<T>`. The consumer awaits each job with `ConfigureAwait(false)`. FIFO in `Enqueue` call order. Do NOT use `SemaphoreSlim.WaitAsync` (not FIFO).
- A job's exception completes only its own task; the loop continues (parity with `run.then(noop, noop)`).
- A job whose `ct` is canceled before it starts completes as canceled without running.
- `DrainAsync(timeout)` completes when every job enqueued before the call has finished, or when `timeout` elapses (it then completes without faulting; the jobs keep running). `ProjectStore.FlushAsync(timeout)` delegates to it; `ShutdownFlush` calls it on exit together with the settings flush (7.12, ARCHITECTURE 4.5 step 3) so a save issued just before quit reaches disk (IMPROVEMENT D-18: Electron can lose a pending chain at process exit).
- `Dispose()` (synchronous, R-ARCH-10): completes the channel writer so later `Enqueue` calls throw `ObjectDisposedException`, and returns without waiting for the consumer, because it runs on the UI thread after the exit flush already drained the queue; a job still running then finishes on the pool or ends with the process (a started atomic write leaves the old or the new file, 7.6). Idempotent. `DisposeAsync()` does the same and then awaits the consumer loop (tests and non-container owners).


**PackAsync** (2.9.13 with native changes):

1. No-op when archived on disk.
2. Walk `shots/` and `export/` recursively with the probe: descend into `Directory`, collect `File`, skip `Link` (parity EDGE-MODEL-38), treat `Unknown` as a failure (throw before anything is written). Include hidden and system files. Relative names use `/`.
3. Create `archive.zip.tmp` with `FileMode.Create` and stream a `ZipArchive(ZipArchiveMode.Create)`; one entry per file, `CompressionLevel.Optimal` (intended as the zlib level 6 equivalent; the exact level is not a parity requirement, Q-MODEL-23), entry name the relative path, no directory entries; each source is read fully with `FileShare.Read` (a cloud placeholder is hydrated by the read; a read failure aborts, EDGE-MODEL-13). Record each file's length and its CRC-32 computed with `System.IO.Hashing.Crc32` (NuGet `System.IO.Hashing`, Microsoft, MIT; add to `Directory.Packages.props`).
4. Reopen the tmp in `ZipArchiveMode.Read`; `got` = non-directory entry `FullName`s sorted Ordinal; compare with `want` sorted Ordinal; IMPROVEMENT D-12: also decompress every entry, recompute its length and CRC-32 with `System.IO.Hashing.Crc32`, and compare both with the values recorded in step 3 (comparing against the zip's own stored CRC would be circular). On mismatch delete the tmp and throw `ArchiveException($"archive verification failed ({got.Count} entries, expected {want.Count}) \u2014 nothing deleted")`.
5. `atomic.RenameWithRetryAsync(tmp, zip)` (IMPROVEMENT: Electron's plain rename has no retry); on failure delete the tmp.
6. `ReparseSafeDelete.DeleteTree` for `shots/` and `export/`.
7. Log Information `"archive: packed {count} file(s) \u2192 {zipPath}"`.

The empty-project case writes a valid empty zip (parity EDGE-MODEL-16). The zip is readable by JSZip and by the macOS reader (seekable `FileStream`, so sizes are in the local headers; no zip64 below 4 GiB; UTF-8 names).

**UnpackAsync**:

1. No-op when no `archive.zip`.
2. Open it with `ZipFile.Open(zipPath, ZipArchiveMode.Read, Encoding.UTF8)` (streaming; the whole file is not loaded into memory: IMPROVEMENT; UTF-8 names regardless of the language flag, parity with JSZip's `decodeFileName`, 2.9.13).
3. For each entry that is not a directory (parity with JSZip `dir`: skip when `FullName` ends in `/` OR `(entry.ExternalAttributes & 0x10) != 0`): `rel = FullName.Replace('\\', '/')`; allowed iff `rel` equals `shots` or `export` or starts with `shots/` or `export/`, AND (IMPROVEMENT D-13 [SECURITY]) no segment of the ORIGINAL name, split on both `/` and `\`, equals `..` (EDGE-MODEL-14, EDGE-MODEL-48); else throw `ArchiveException($"archive contains an unexpected path: {entry.FullName}")`. `abs = ConfineNoLinks(projectDir, rel)`, else throw `ArchiveException($"refusing to extract a path outside the project: {entry.FullName}")`. `Directory.CreateDirectory(parent)`; extract with `entry.ExtractToFile(abs, overwrite: true)`.
4. Verify every written file exists; delete `archive.zip` (a failure to delete surfaces).
5. Log Information `"archive: restored {count} file(s) from {zipPath}"`.

No size caps by default (Q-MODEL-7).

### 7.10 Optimistic editing: ProjectSession

The fixed decision requires UI edits to update the in-memory model first and persist through the serialized queue with rollback. Electron's model (every op re-reads the disk) is kept as the PERSISTENCE semantics; the optimistic layer sits above it.

The contract below is the consolidated one of ARCHITECTURE 7.4 (R-ARCH-5, R-ARCH-6, R-ARCH-20, R-ARCH-23, R-ARCH-27), which folded in the requests of 05, 07, 09 and 11. Rules (S1 to S10 of ARCHITECTURE 7.4):

| # | Rule |
|---|---|
| S1 | `Apply(op)` runs `op.Apply` on a deep clone of `Current` on the UI thread. `Changed`: `Current` becomes the clone, `Changed(Local, op.AffectedStepIds)` is raised, and the same operation is queued as `store.MutateAsync(ProjectDir, m => ValueTask.FromResult(op.Apply(m)))`. `Unchanged`: nothing is queued; the task completes with `Current`. |
| S2 | If `op.Apply` throws on the clone, `Current` is untouched, nothing is queued, no event is raised, and the returned task is faulted with that exception, unwrapped (05 7.5 request 1, 07 Q-SOP-21). |
| S3 | When the last pending operation persists, `Current` becomes the persisted manifest (it adopts `updatedAt`). The event is `Changed(Persisted)` when it equals the previous `Current` apart from `updatedAt`, else `Changed(External)` (the disk carried a change this session did not make). |
| S4 | When a queued operation fails, the session re-reads the disk (or uses the last persisted manifest if the read fails), re-applies every still-pending operation in order, sets `Current`, raises `Changed(RolledBack)` and `PersistFailed(op, error)`, and faults that operation's task. |
| S5 | `ApplyDurable(call)` awaits `call(store)`; `Current` becomes its result with every optimistic operation issued after the durable call started re-applied on top; `Changed(Durable)` is raised. |
| S6 | `WhenIdleAsync` completes when every operation queued and every durable call started before the call has finished (persisted or rolled back). |
| S7 | `IProjectSettle.WhenSettledAsync(path)` finds every registered session for `Path.GetFullPath(path)` (compared `OrdinalIgnoreCase`, 02 D9), the open one and any disposed one still draining (S9), and awaits their `WhenIdleAsync`; with none registered it completes at once. 09's requested `IProjectService.WhenIdleAsync(path)` is this member (R-ARCH-6). |
| S8 | Events are posted (never sent) to the context captured by `Create`; handlers check `sender == currentSession` (05 INV-REP-31). |
| S9 | `DisposeAsync` stops raising events at once and lets queued writes drain on the shared queue; it never cancels them. The session stays registered with `IProjectSettle` until every operation and durable call it accepted has finished (persisted or rolled back), and unregisters only then, so an export or SOP run started from Home right after Back still waits for those writes (superseded wording: "unregisters at `DisposeAsync`", R-ARCH-27). |
| S10 | Operations are pure and deterministic, with ids and timestamps fixed at construction, because the same instance runs twice (clone, then disk). |

| Session state | Event | Guard | Action | Next |
|---|---|---|---|---|
| Idle (Pending 0) | `Apply(op)` | `op.Apply(clone of Current)` returns Changed | Current = the clone; raise `Changed(Local, op.AffectedStepIds)`; enqueue `MutateAsync(dir, m => op.Apply(m))` | Pending(1) |
| Idle | `Apply(op)` | returns Unchanged | nothing queued; task completes with Current | Idle |
| any | `Apply(op)` | `op.Apply` throws | nothing changes, nothing queued, no event; the task faults with the exception (S2) | unchanged |
| Pending(n) | `Apply(op)` | Changed | as above | Pending(n+1) |
| Pending(n) | a queued op persisted | n > 1 | record the persisted manifest as `LastPersisted` | Pending(n-1) |
| Pending(1) | the queued op persisted | | Current = the persisted manifest; raise `Changed(Persisted)` or `Changed(External)` (S3) | Idle |
| Pending(n) | a queued op failed | | re-read the disk (or use `LastPersisted` if the read fails); re-apply the ops still pending on top; Current = result; raise `Changed(RolledBack)` and `PersistFailed(op, error)`; fault that op's task | Pending(n-1) |
| any | `ApplyDurable(call)` | | await `call(store)`; Current = its result with later optimistic ops re-applied; raise `Changed(Durable)` | unchanged count |

### 7.11 Conformance harness

Replace the skip in `dotnet/tests/ShotAI.Core.Tests/Conformance/ConformanceTests.cs` (`Round_trips_through_the_codec`) with the TS algorithm (`conformance.test.ts:70-139`):

```csharp
[Theory, MemberData(nameof(Cases))]
public void Round_trips_through_the_codec(string file)
{
    var c = ConformanceCase.Load(file);
    JsonNode? written;
    try
    {
        var m = ManifestCodec.Decode(c.Input.DeepClone(), "Imported project");
        written = JsJson.Parse(JsJson.Stringify(ManifestCodec.Encode(m)));      // through text, as the TS does
    }
    catch (Exception ex)
    {
        var threw = $"{c.Name}: the codec THREW \u2014 {ex.Message}";
        if (c.IsOpen) { Report($"[conformance] open divergence \u2014 {threw}\n  {c.Divergence ?? ""}\n  tracked: {c.Issue ?? "untracked"}"); return; }
        Assert.Fail($"{threw}\n  why this matters: {c.Why}");
        return;
    }

    var failures = new List<string>();
    foreach (var key in c.Expect.Select(p => p.Key).Order(StringComparer.Ordinal))   // Object.keys(...).sort()
    {
        var want = c.Expect[key];
        var present = ExpectPath.TryGet(written, key, out var got);
        if (ExpectPath.WantsAbsent(want))
        {
            if (present) failures.Add($"{key}: expected ABSENT, got {ExpectPath.Canonical(got)}");
            continue;
        }
        if (!present) { failures.Add($"{key}: expected {ExpectPath.Canonical(want)}, got ABSENT"); continue; }
        if (ExpectPath.Canonical(got) != ExpectPath.Canonical(want))
            failures.Add($"{key}: expected {ExpectPath.Canonical(want)}, got {ExpectPath.Canonical(got)}");
    }

    if (failures.Count == 0)
    {
        if (c.IsOpen)
            Report($"[conformance] {c.Name} is marked open and PASSES HERE. It stays open until the other platform " +
                   $"passes too \u2014 check there before flipping status to \"agreed\" (tracked: {c.Issue ?? "untracked"}).");
        return;
    }
    var detail = $"{c.Name}: {string.Join("; ", failures)}";
    if (c.IsOpen) { Report($"[conformance] open divergence \u2014 {detail}\n  {c.Divergence ?? ""}\n  tracked: {c.Issue ?? "untracked"}"); return; }
    Assert.Fail($"{detail}\n  why this matters: {c.Why}");
}

private static void Report(string message) => TestContext.Current.SendDiagnosticMessage(message);
```

Two scaffold changes go with this:

- `ConformanceCase.Load` parses the case file with `JsJson.Parse`, not `JsonNode.Parse`, so a fixture input goes through the same parser the store uses, as the TS harness's `JSON.parse(readFileSync(..., 'utf8'))` does (lone surrogate escapes, duplicate keys and `1e400` then behave as in Electron, and every number is a double before `Decode` sees it). `Decode` must still accept `JsonElement`-backed `JsonValue`s, because tests build inputs with `JsonNode.Parse`: classify by `GetValueKind()`, read with `TryGetValue<double>` / `TryGetValue<string>`, never by the CLR type of the value.
- `Report`: xunit.v3 shows `SendDiagnosticMessage` output only when `diagnosticMessages` is enabled in `xunit.runner.json`. The TS harness's `console.warn` is always visible, so either enable `diagnosticMessages` in the test project or report through `TestContext.Current.AddWarning(message)` (xunit.v3 test warnings; confirm the API against the pinned xunit.v3 4.0.1 when implementing, UNVERIFIED here).

### 7.12 Threading, cancellation, disposal

- Core has no thread affinity. All IO is async (`FileStream` with `FileOptions.Asynchronous`, `File.ReadAllBytesAsync`); directory enumeration and zip work run on the thread pool inside queue jobs or listing calls. Core awaits with `ConfigureAwait(false)` everywhere (`CA2007` as error), except `ProjectSession.cs` (ARCHITECTURE T3).
- The queue consumer is the only code that writes manifests. Reads outside the queue (list, get-for-read) may run concurrently with a write; the atomic rename guarantees they see the old or the new file.
- `ProjectSession` posts `Changed` and `PersistFailed` to the `SynchronizationContext` captured by `IProjectSessionFactory.Create` on the UI thread (the WPF `DispatcherSynchronizationContext`); it is the only Core type that touches a synchronization context (ARCHITECTURE 6.3). `ProjectStore.ProjectsChanged` is raised on the thread that ran `AutoArchiveStaleAsync`, outside any lock, through `EventRaiser` (11 T5); subscribers marshal with `IUiDispatcher.Post` (11 T6).
- Cancellation: listing and auto-archive check `ct` between projects; a queued job observes `ct` only before it starts; a started job always completes (ARCHITECTURE 6.5 K1, K6).
- Disposal (superseded by R-ARCH-10; the earlier `await provider.DisposeAsync()` design is withdrawn): `App.OnExit` is synchronous and calls `provider.Dispose()` (ARCHITECTURE 4.1 C5, 4.5 step 5). `ServiceProvider.Dispose()` throws `InvalidOperationException` for a resolved service that implements only `IAsyncDisposable` (Microsoft Learn, `ServiceProvider.Dispose`), so every disposable singleton of this spec implements `IDisposable`: `ProjectStore : IProjectService, IDisposable, IAsyncDisposable`, whose `Dispose` completes the queue writer and returns without blocking and without needing the UI thread (7.7). `AtomicFile`, `ArchiveEngine` and `ProjectSessionFactory` hold nothing to dispose. `ProjectSession` is `IAsyncDisposable` only and exempt, because it is not container-owned: the factory creates it and the project view disposes it on Back (S9, 11 7.10 rule 2). `Composition.ContainerTests.NoAsyncOnlyDisposables` enforces the rule (AC-MODEL-36).
- App exit (ARCHITECTURE 4.5, 11 7.10): WPF's `Application.OnExit` is synchronous, and an `async void` override would return to the dispatcher at its first `await`, after which the process can end before the flush completes. Step 3 therefore blocks once, in the one allowlisted file `ShutdownFlush.cs`: `ShutdownFlush.Run(TimeSpan.FromSeconds(5))` runs `Task.WhenAll(projects.FlushAsync(t), settings.FlushAsync(t)).Wait(t)` over the project queue and the settings queue together, 5 s in total; on timeout it logs Warning `exit: pending writes not flushed within 5 s` and continues. This cannot deadlock because no queue job, Core continuation or `Dispose` needs the UI thread (DL4: Core awaits with `ConfigureAwait(false)`, and `ProjectSession` events are posted, never awaited, by the queue). Step 5 is `provider.Dispose()`. `SessionEnding` (logoff, shutdown) calls the capture `Teardown()` and lets WPF continue to `OnExit`, which runs the same flush; there is no second flush.

**Q-MODEL-1.** `displayScale` out of range: clamp in the codec (Electron, file becomes `1.25`) or store raw and clamp at use (macOS, file keeps `9`)? Recommended default: Electron parity (clamp in the codec) until cutover, so the shared case stays `open` for the same reason on both Windows builds; after cutover, raise on shotAI_MacOS#105 whether both native apps should store raw and flip the case to `agreed`.

**Q-MODEL-2.** The fixed decision names System.Text.Json. This spec uses its `Utf8JsonReader` and `JsonNode` but a hand-written writer and string unescaper, because the library cannot reproduce `JSON.stringify` bytes or accept lone surrogates. Recommended default: accept (the divergence is mechanical and fully tested); record it in PLAN.md as an interpretation of the decision. Resolved by ARCHITECTURE 15.2 I-1: "System.Text.Json" means its `Utf8JsonReader` and `JsonNode` tree plus a Core unescaper and a hand-written `JSON.stringify` writer; golden files prove byte parity.

**Q-MODEL-3.** Canonical root key order (D-3) makes the first native save of an Electron file that was just mutated reorder up to three keys. Recommended default: accept; golden tests compare decode-then-encode, where both agree.

**Q-MODEL-4.** Stripping a BOM (D-4) makes native read files Electron cannot. Recommended default: strip; never write a BOM.

**Q-MODEL-5.** `FlushFileBuffers` on every manifest write costs latency on NTFS (typically a few ms to tens of ms, more under Defender). Recommended default: flush; the optimistic UI hides the latency. Measure during Phase A and revisit if a capture burst slows down. Adopted by ARCHITECTURE 7.10; the proposed budget is PB-14 (p95 under 50 ms for a 100-step manifest), measured manually in Phase A.

**Q-MODEL-6.** The claim that libuv reports every reparse point as a link in `readdir` (and therefore that Electron skips OneDrive placeholder folders and drops placeholder files from archives) is from reading, not measurement. Recommended default: implement D-15 regardless; verify on a Windows machine with a Files On-Demand folder (dehydrate a project, list it in Electron, archive a copy) and file an Electron issue if confirmed.

**Q-MODEL-7.** Restore size caps (macOS: 256 MiB per entry, 2 GiB total). Recommended default: no caps natively, because streaming removes the memory risk and a cap could lock a user out of a legitimately large archive; revisit if a zip-bomb threat model appears for synced folders.

**Q-MODEL-8.** Hostile-segment rejection (D-6) could refuse a legitimate name some future writer produces. Recommended default: reject; no current writer on either platform produces `:`, device names or trailing dots.

**Q-MODEL-9.** Queuing `DeleteProjectAsync` and the id back-fill (D-7, D-8) means a delete waits behind pending writes. Recommended default: accept; deletes are rare and the queue is short.

**Q-MODEL-10.** Import failure cleanup (D-9) deletes a folder the import just created; if the confinement check itself were wrong, cleanup could delete the wrong thing. Recommended default: clean up only the exact `<root>/<new uuid>` path, through `ReparseSafeDelete`.

**Q-MODEL-11.** User-facing text for an unreadable manifest. Electron shows the raw parser or ENOENT message. Recommended default (IMPROVEMENT, final wording owned by 06): `This project can't be opened because its project.json is missing or damaged.` with the parser message in the log only. Adopted by 05 EDGE-REP-39 and 06 EDGE-HOME-24: a non-"gone" open failure raises `OpenFailed(message)` and Home shows this sentence as an error notice (PLAN WP-A17).

**Q-MODEL-12.** The optimistic rollback notice text. Recommended default (owned by 05): `Your last change couldn't be saved and was undone.` followed by the error message. Resolved by 05 7.5 and ARCHITECTURE 5.5: the report's `SaveError` notice slot shows `Your last change couldn't be saved and was undone. ` followed by `UserMessage.From(error)`.

**Q-MODEL-13.** Paths longer than 260 characters (a deep custom projects root). Recommended default: declare `longPathAware` in `src/ShotAI.App/app.manifest` (03, 12) and add a test that creates and archives a project under a 300-character root on the Windows runner. Resolved (ARCHITECTURE 1.3): the scaffold already declares it (`dotnet/src/ShotAI.App/app.manifest:16`); the 300-character-root test is scheduled in WP-A8.

**Q-MODEL-14.** The macOS fixture project lives in a read-only repo. Recommended default: copy `Fixtures/b7e2c4d1-9f3a-4e8b-a2c5-6d1f8e9a0b3c/` into `dotnet/tests/ShotAI.Core.Tests/Golden/macos-fixture/` (not into `contract/`, which must stay byte-identical across repos) with a README naming its origin commit `f445bca`. Adopted by ARCHITECTURE 12.4 and PLAN WP-A3 (the whole folder, byte-identical, under `Golden/macos-fixture/b7e2c4d1-9f3a-4e8b-a2c5-6d1f8e9a0b3c/`).

**Q-MODEL-15.** `setProjectTheme` coerces an unknown value to the default brand (EDGE-MODEL-7). Recommended default: the native API accepts only null or a known brand id and throws `ArgumentException` otherwise; the UI cannot produce anything else. Resolved by 11 7.3.2 and D-IPC-9: adopted as recommended (7.8), with `BrandPalette.IsBrandId` (10, R-ARCH-14) as the test.

**Q-MODEL-16.** Should the no-op guard (D-11) extend to reorder with an unchanged order and to intro edits with identical text? Recommended default: yes for both (return Unchanged when the resulting manifest is value-equal to the input before `updatedAt`), because the rationale (#77) is the same; confirm with 05 that no UI relies on the re-dating.

**Q-MODEL-17.** `listProjects` reads every manifest on every Home refresh (06 polls). Recommended default: parity first; if Phase A profiling shows cost, cache summaries keyed by (full path, `project.json` last-write time, length) and invalidate on any queued write to that project.

**Q-MODEL-18.** The Electron golden outputs (AC-MODEL-3) need a small Electron-side test that writes them. Recommended default: add it in the same PR as the native codec, under `src/main/codec-golden.test.ts`, writing only outputs, into `dotnet/tests/ShotAI.Core.Tests/Golden/codec/expected/`, only when an environment variable is set, so normal Electron CI stays read-only. Scheduled by PLAN WP-A3: `SHOTAI_CODEC_GOLDENS=1 npx vitest run src/main/codec-golden.test.ts` (ARCHITECTURE 15.4 keeps it open with this default).

**Q-MODEL-19.** JS `toLowerCase` applies full Unicode case mapping (final sigma, U+0130 to two code units) while .NET `ToLowerInvariant` applies simple mapping. Recommended default: use `ToLowerInvariant` for both the text and the query; the only effect is on Greek final sigma and dotted capital I in search.

**Q-MODEL-20.** Stale `project.json.<pid>.tmp` files from crashes accumulate in both apps. Recommended default: on open, delete `project.json.*.tmp` siblings whose last write is older than 24 hours (IMPROVEMENT), never one younger (another process could be mid-write on a synced copy). Adopted by ARCHITECTURE 7.10; implemented in `OpenProjectAsync` (WP-A6).

**Q-MODEL-21.** Archive restore name rules. Electron, via JSZip, silently resolves `.`, `..` and empty segments in forward-slash entry names; native rejects them (D-25). A zip produced by some third-party tool with `./` prefixes would restore in Electron and fail natively. Recommended default: reject; only shotAI writes `archive.zip`, and both shotAI writers emit plain names. Revisit only if a real archive fails.

**Q-MODEL-22.** Step ids used as file names (EDGE-MODEL-51). Electron normalizes the id through `path.posix.join` and then confines, so a hand-edited id can redirect a render anywhere inside the project with a `.png` suffix. Recommended default (04 decides): refuse any id that is not a single safe path segment, with the existing `refusing to write render for step "{id}" \u2014 path escapes the project folder` text. Resolved by 04 D-EDIT-22: the render writer refuses such an id with that message (`RefusedRenderPathException`).

**Q-MODEL-23.** `CompressionLevel.Optimal` is described as zlib level 6 in 7.9. The .NET mapping of `Optimal` to a zlib level is an implementation detail that has changed across runtime versions (UNVERIFIED for .NET 10). Recommended default: parity of level is not required (the archive only has to be DEFLATE and readable by JSZip and macOS); do not assert compressed sizes in tests.

**Q-MODEL-24.** 10's Q-INFRA-3 asks for this spec's agreement: a `projectsDir` in `settings.json` that is empty or not fully qualified loads as the default folder (`%USERPROFILE%\shotAI Projects`) instead of resolving against the process's current directory. Answer: agreed. The known-project gate (2.9.1, 7.8) and `ListProjectsAsync` then always see a fully qualified root from `IProjectStoreSettings`, so `Path.GetFullPath(projectsDir)` never depends on the working directory; the store adds no check of its own. Recorded here for PLAN WP-A10.

**Q-MODEL-25.** `ProjectOperation.BumpsUpdatedAt` (ARCHITECTURE 7.4) has no carrier: S1 queues `IProjectService.MutateAsync(dir, fn)`, whose job always bumps `updatedAt` unless `fn` returns `Unchanged` (2.9.3), and `IProjectService` (11 7.3.2) has no parameter for it. No operation in 2.0.0 overrides the property (the archive-like writes are Home list calls, not session operations). Recommended default: keep the property, assert in `ProjectSessionTests` that every shipped operation returns `true`, and when the first operation needs `false`, add an optional `bool bumpUpdatedAt = true` parameter to `IProjectService.MutateAsync` in 11 7.3.2, ARCHITECTURE 7.4 and this spec's 7.8 in the same PR.
